۱ چرا و فلسفه‌ی کار

قبل از این‌که یک خط کد عوض کنی، باید بدونی چرا داریم این کار رو می‌کنیم.

اکثر فایل‌های پروژه‌ی ما قدیمی هستند؛ یعنی با ساختارهای دستی مثل x_panel، x_title، کلاس‌های سفارشیِ پراکنده و کلی استایل اینلاین (مثل style="margin:16px") نوشته شده‌اند. این روش سه مشکل بزرگ دارد:

⚠️
مشکلِ کد قدیمی: هر صفحه ظاهر و ساختار متفاوتی دارد، نگه‌داری سخت است، ریسپانسیو نیست، و وقتی یک رنگ یا فاصله را عوض می‌کنی باید ده‌ها جا را دستی پیدا کنی.

هدف ما این است که همه‌ی صفحات به یک ساختار یکنواخت مبتنی بر بوت‌استرپ ۵ برسند تا:

  • همه‌ی صفحات شبیه هم و حرفه‌ای به نظر برسند (یکدستی بصری).
  • کد کوتاه‌تر، تمیزتر و قابل‌فهم برای همه‌ی اعضای تیم باشد.
  • به‌صورت خودکار ریسپانسیو و راست‌چین (RTL) باشد.
  • تغییرات سراسری از یک نقطه (فایل کاستوم بوت‌استرپ) مدیریت شود.
🎯
قانون کلی: تا جای ممکن همه چیز باید با کلاس‌های آماده‌ی بوت‌استرپ انجام شود. استایل دستی و اینلاین آخرین راه‌حل است، نه اولین.

۲ جدول معادل‌ها (قدیمی ← جدید)

این جدول قلب راهنماست: وقتی کد قدیمی را دیدی، چه چیزی را با چه چیزی عوض کن.

کد قدیمی حذف شود جایگزین بوت‌استرپ به‌جایش توضیح
<div class="page-wrap"> <div class="container-fluid"> یا container قاب اصلی صفحه. container-fluid تمام عرض، container عرض محدود.
<div class="x_panel"> <div class="card"> هر «جعبه» محتوا یک کارت می‌شود.
<div class="x_title"> card-header یا border-bottom + هدینگ عنوان بالای کارت.
محتوای داخل پنل <div class="card-body"> بدنه‌ی کارت.
.search-card / .form-section card + card-body هر بخش فرم یک کارت تو در تو.
.search-row (فلکس دستی) row g-2 + col-auto سیستم گرید بوت‌استرپ برای چینش فیلدها.
.search-field col-auto یا col-md-3 هر فیلد یک ستون.
<input class="form-input"> <input class="form-control form-control-sm"> تمام input/textarea/select.
چک‌باکس/رادیو دستی با <label> <div class="form-check"> + form-check-input + form-check-label ساختار استاندارد چک‌باکس و رادیو.
.btn.btn-primary سفارشی btn btn-primary (خودِ بوت‌استرپ) دکمه‌ها؛ فقط کلاس بوت‌استرپ.
.modern-table / .table-wrapper table table-bordered table-hover داخل table-responsive جدول‌ها کاملاً استاندارد می‌شوند.
.total-row table-info fw-bold ردیف جمع کل.
.alert-info سفارشی alert alert-info جعبه‌ی پیام.
alert('...') notyf.warning('...') پیام‌های جاوااسکریپت (بخش ۷ را ببین).
newstyle.css bootstrap.rtl.min.css + bootstrap-custom.css منبع استایل عوض می‌شود.

۳ اسکلت استاندارد یک صفحه

هر صفحه‌ی جدید باید دقیقاً از این ترتیب پیروی کند تا یکدست بمانیم.

بخش <head> — منابع

<!-- ۱) همیشه بوت‌استرپ RTL اول -->
<link rel="stylesheet" href="<?php echo $root_path; ?>css/bootstrap-5.3.8/css/bootstrap.rtl.min.css">
<!-- ۲) فایل کاستوم مشترک پروژه -->
<link rel="stylesheet" href="<?php echo $root_path; ?>css/bootstrap-custom.css">
<!-- ۳) در پایان صفحه: باندل JS بوت‌استرپ -->
<script src="<?php echo $root_path; ?>css/bootstrap-5.3.8/js/bootstrap.bundle.min.js"></script>
<!-- ۴) فایل JS مخصوص همین صفحه -->
<script src="<?php echo $root_path; ?>modules/.../js/page_name.js"></script>

بدنه‌ی صفحه — قالب کلی

<div class="container-fluid mt-3">

  <!-- عنوان صفحه -->
  <div class="border-bottom border-2 p-1 mb-2 d-flex align-items-center">
    <h2 class="h6 m-0 text-primary">عنوان</h2>
  </div>

  <!-- کارت محتوا -->
  <div class="card mb-3">
    <div class="card-body">
      ... فرم یا جدول ...
    </div>
  </div>

</div>

۴ قوانین طلایی (حتماً بخوان)

این پنج قانون غیرقابل‌مذاکره‌اند. رعایت‌نکردنشان یعنی به‌هم‌ریختن یکدستی پروژه.

قانون ۱ — جاوااسکریپت همیشه در فایل JS مخصوص همان صفحه

هیچ کد جاوااسکریپتی نباید به‌صورت اینلاین (onclick="..." یا تگ <script> پر از منطق) داخل فایل PHP نوشته شود. هر صفحه فایل JS خودش را دارد (که ممکن است متفاوت باشد) و همه‌ی منطق آنجا می‌رود.

قدیمی داخل PHP

<script>
  function selectAll() { ... }
</script>

جدید داخل page_name.js

// modules/.../js/page_name.js
function selectAll() { ... }

قانون ۲ — هیچ استایل اینلاینی نزن

نوشتن style="..." روی تگ‌ها ممنوع است. به جایش از کلاس‌های Utility بوت‌استرپ استفاده کن (بخش ۵). اگر واقعاً چیزی بود که بوت‌استرپ نداشت، آن را در <style> همان صفحه بنویس.

🚫
ممنوع: <div style="margin-top:12px;font-size:24px">  ←  درست: <div class="mt-3 fs-3">

قانون ۳ — به فایل bootstrap-custom.css دست نزن (مگر برای override بوت‌استرپ)

فایل کاستوم بوت‌استرپ فقط برای override یا تنظیم رفتار کلاس‌های خودِ بوت‌استرپ است. به‌هیچ‌وجه کلاس سفارشی جدید (مثل .my-box) آنجا تعریف نکن؛ این کار ساختار یکنواخت را خراب می‌کند.

📌
کجا چه چیزی بنویسم؟
  • استایلِ مخصوص فقط یک صفحه ← داخل تگ <style> همان فایل.
  • چیزی که واقعاً مهم و سراسری است و باید رفتار یک کلاس بوت‌استرپ را عوض کند ← bootstrap-custom.css.
  • کلاس سفارشی کاملاً جدید ← اصلاً نزن، با کلاس‌های آماده حلش کن.

قانون ۴ — اول کلاس آماده، بعد استایل دستی

قبل از این‌که هر استایلی بنویسی، اول مطمئن شو بوت‌استرپ یک کلاس آماده برایش ندارد. ۹۰٪ کارها (فاصله، رنگ، فلکس، گرید، سایه، حاشیه) کلاس آماده دارند.

قانون ۵ — به جای alert() از Notyf استفاده کن

تمام پیام‌های alert() و confirm() باید با Notyf جایگزین شوند (بخش ۷).

۵ حذف استایل اینلاین با کلاس‌های Utility

به جای نوشتن font-size، margin، padding و... به‌صورت دستی، از این معادل‌ها استفاده کن.

فاصله‌ها — margin و padding

الگو: {property}{sides}-{size}. مقادیر اندازه از 0 تا 5 (و auto) هستند. مقیاس: 1=4px، 2=8px، 3=16px، 4=24px، 5=48px.

استایل دستیمعادل بوت‌استرپچند نمونه‌ی دیگر
margin-top:16pxmt-3mt-1 .. mt-5
margin-bottom:24pxmb-4mb-0، mb-2
margin: 0 automx-automs-auto (راست‌چین: چپ)
padding:16pxp-3p-0 .. p-5
padding: 0 8pxpx-2py-2 (بالا/پایین)
فاصله‌ی بین آیتم‌های فلکس/گریدgap-2g-2 داخل row
🧭
در RTL: ms-* یعنی margin سمت «شروع» (راست) و me-* یعنی سمت «پایان» (چپ). به جای ml/mr از ms/me استفاده کن تا راست‌چین درست بماند.

۷ Notyf — جایگزین مدرن alert()

دیگر از alert() زشت و مزاحم مرورگر استفاده نکن. Notyf پیام‌های شناور، زیبا و رنگی نشان می‌دهد.

Notyf چیست؟ یک کتابخانه‌ی سبک جاوااسکریپت برای نمایش «توست» (پیام شناور گوشه‌ی صفحه). این تنظیمات یک‌بار به‌صورت سراسری انجام می‌شود (مثلاً در فایل JS مشترک) و بعد در همه‌ی صفحات در دسترس است:

document.addEventListener('DOMContentLoaded', () => {
  window.notyf = new Notyf({
    duration: 3000,                         // مدت نمایش (میلی‌ثانیه)
    position: { x: 'right', y: 'top' },    // محل نمایش
    dismissible: true,                       // قابل بستن با کلیک
    ripple: false,
    types: [
      { type: 'success', background: '#27ae60', icon: false },
      { type: 'error',   background: '#e74c3c', icon: false },
      { type: 'warning', background: '#f39c12', icon: false },
      { type: 'info',    background: '#2980b9', icon: false },
      { type: 'confirm', background: '#8e44ad', icon: false },
    ]
  });

  // فعال‌سازی متدهای سفارشی warning / info / confirm
  ['warning', 'info', 'confirm'].forEach(type => {
    notyf[type] = (message) => notyf.open({ type, message });
  });
});

هر نوع Notyf برای چیست؟

✅ success — سبز

notyf.success('ذخیره شد')

وقتی عملیاتی با موفقیت انجام شد (ثبت، ویرایش، حذف موفق).

⛔ error — قرمز

notyf.error('خطا رخ داد')

وقتی خطایی پیش آمد. جایگزین اصلی alertهای خطا.

⚠️ warning — نارنجی

notyf.warning('دقت کن')

برای هشدار و یادآوری (مثلاً فیلدی پر نشده، اعتبارسنجی فرم).

ℹ️ info — آبی

notyf.info('توجه')

برای اطلاع‌رسانی ساده و راهنمایی بدون بار مثبت یا منفی.

🟣 confirm — بنفش

notyf.confirm('در حال انجام')

برای تاییدها و حالت‌های خاص که می‌خواهی متمایز دیده شوند.

جایگزینی alert با Notyf

قدیمی

alert('تاریخ را وارد کنید');
alert('با موفقیت ثبت شد');
alert('خطا در ارتباط');

جدید

notyf.warning('تاریخ را وارد کنید');
notyf.success('با موفقیت ثبت شد');
notyf.error('خطا در ارتباط');
📎
یادت باشد فایل‌های CSS و JS خودِ Notyf هم باید در <head> صفحه (یا قالب مشترک) لود شده باشند تا notyf در دسترس باشد.

۸ یک مثال کامل قدم‌به‌قدم

تبدیل یک قطعه‌ی واقعی از حالت قدیمی به بوت‌استرپ.

قدیمی

<div class="x_panel">
  <div class="x_title">
    <h2 style="font-size:18px">گزارش</h2>
  </div>
  <div style="margin:16px;display:flex">
    <input class="form-input">
    <button onclick="alert('ok')">برو</button>
  </div>
</div>

جدید

<div class="card mb-3">
  <div class="card-header">
    <h2 class="h5 m-0">گزارش</h2>
  </div>
  <div class="card-body d-flex gap-2">
    <input class="form-control form-control-sm">
    <button id="goBtn" class="btn btn-primary">برو</button>
  </div>
</div>

// و در فایل page_name.js :
document.getElementById('goBtn')
  .addEventListener('click', () => notyf.success('ok'));

چه چیزهایی عوض شد؟ x_panel→card، x_title→card-header، استایل اینلاینِ فاصله و فلکس ← card-body d-flex gap-2، form-input→form-control، onclick و alert ← منطق در فایل JS مجزا با notyf.

۹ چک‌لیست نهایی

قبل از این‌که بگویی «صفحه آماده است»، این لیست را تیک بزن.

  • هیچ style="..." اینلاینی در صفحه نمانده باشد.
  • هیچ کلاس سفارشی قدیمی (x_panel، search-card، modern-table و...) باقی نمانده باشد.
  • قاب اصلی container/container-fluid و هر جعبه یک card باشد.
  • همه‌ی input‌ها form-control و چک‌باکس/رادیوها form-check باشند.
  • چینش فیلدها با row و col-* انجام شده باشد، نه فلکس دستی.
  • جدول‌ها داخل table-responsive با کلاس‌های table باشند.
  • تمام کد JS در فایل JS مخصوص همان صفحه باشد، نه اینلاین.
  • هیچ alert() نمانده؛ همه با notyf.* جایگزین شده.
  • در bootstrap-custom.css کلاس سفارشی جدیدی اضافه نشده باشد.
  • استایل مخصوص همین صفحه (اگر لازم بود) فقط داخل <style> همان فایل باشد.
  • صفحه راست‌چین (RTL) و در موبایل هم درست نمایش داده شود.
🏁
قاعده‌ی نهایی: اگر برای کاری وسوسه شدی style بنویسی، اول ۳۰ ثانیه بگرد ببین کلاس بوت‌استرپش چیست. تقریباً همیشه هست.
